# План реализации: XunGram (ПК-клиент в стиле ExteraGram)

- **Спецификация:** `docs/superpowers/specs/2026-10-12-xungram-design.md`
- **Дата:** 2026-10-12

Порядок работ — по вехам M0→M4. Каждая задача содержит проверяемый результат.
Идём строго по порядку: следующая веха начинается после того, как предыдущая собирается и
проходит свою проверку.

## M0 — Фундамент

**Цель:** собираемый форк tdesktop с собственной идентификацией и зафиксированными швами.

- [ ] **M0.1. Форк и удалённые репозитории.**
  - Завести отдельный репозиторий проекта, `tdesktop` подключить как источник с remote
    `upstream` (github.com/telegramdesktop/tdesktop).
  - Проверка: `git remote -v` показывает `upstream`; `git log` апстрима доступен.
- [ ] **M0.2. Сборка tdesktop как есть (baseline).**
  - Собрать Debug по инструкции `docs/building-linux.md` (docker centos_env).
  - Проверка: бинарник запускается, вход в аккаунт проходит.
- [ ] **M0.3. Идентификация и брендинг (юридически обязательный шаг).**
  - Зарегистрировать собственные `api_id`/`api_hash` на my.telegram.org.
  - Сменить имя приложения, app id, desktop-файл, иконки; убрать официальный брендинг.
  - Прописать api_id/api_hash в конфиг сборки.
  - Проверка: клиент входит под своим api_id; в системе отображается под своим именем.
- [ ] **M0.4. Директория `extra/` и подключение к сборке.**
  - Создать `tdesktop/Telegram/SourceFiles/extra/` с пустыми модулями (`seam/`, `host/`,
    `features/`, `ui/`) и `namespace Extra`.
  - Добавить `add_subdirectory`/группу источников в `Telegram/CMakeLists.txt`.
  - Проверка: сборка проходит, `Extra` виден линкеру (dummy-функция).
- [ ] **M0.5. `SEAMS.md` и первый шов.**
  - Зафиксировать формат записи шва. Внести первый шов — уведомление о входящем апдейте
    в диспетчере MTP (`Extra::Hooks::OnUpdate`) как no-op.
  - Проверка: шов вызывается (лог), поведение клиента не меняется.

## M1 — Хост плагинов

**Цель:** загружаемые Python-плагины с жизненным циклом, менеджер и safe mode.

- [ ] **M1.1. Встраивание CPython.**
  - Связать статический CPython (vendor, напр. `python-build-standalone`) + `pybind11`
    в CMake; инициализация интерпретатора на старте, финализация на выходе.
  - Проверка: на старте выполняется `print` из встроенного Python; сборка статическая.
- [ ] **M1.2. `Extra::Plugins::Engine` — загрузка/выгрузка.**
  - Обнаружение плагинов в `~/.local/share/XunGram/plugins` и во встроенном каталоге.
  - Чтение `manifest.json`, проверка `api_version`, импорт `main.py`, инстанцирование
    класса-наследника `BasePlugin`.
  - Проверка: тестовый плагин грузится, `on_load/on_enable` вызываются (лог).
- [ ] **M1.3. Изоляция ошибок и safe mode.**
  - Перехват исключений при загрузке и в колбэках; пометка плагина «сломан», авто-отключение.
  - Safe mode: если старт падает при активных плагинах — следующий запуск с выключенными.
  - Проверка: искусственно падающий плагин не роняет клиент; safe mode срабатывает.
- [ ] **M1.4. UI-менеджер плагинов.**
  - Вкладка «Плагины»: список, вкл/выкл, перезагрузка, просмотр ошибок, установка из
    директории/URL.
  - Проверка: включение/выключение из UI меняет состояние движка; ошибки видны.

## M2 — API v1 и SDK

**Цель:** публичный API, достаточный для написания плагинов сообществом.

- [ ] **M2.1. Сеть:** швы и API `on_request`, `on_update` (наблюдение/модификация/отмена).
- [ ] **M2.2. Сообщения:** `on_outgoing_message`, `on_message_sent`, `on_incoming_message`
  (изменение текста/разметки до отображения).
- [ ] **M2.3. UI:** `register_settings_page/row`, `show_dialog`, `show_toast`,
  `register_menu_item`, `register_shortcut`.
- [ ] **M2.4. Сессия:** `send_message`, `edit_message`, `send_media`, `list_chats`,
  `get_chat`, `current_account`.
- [ ] **M2.5. Настройки:** `get_setting`/`set_setting`, изолированный KV-store, авто-UI
  страницы, экспорт/импорт.
- [ ] **M2.6. Утилиты и потоки:** `run_on_ui`, фоновые очереди, управление GIL, логирование.
- [ ] **M2.7. SDK и документация:** `.pyi`-стабы, доки по API, `BasePlugin`, `hooks`.
- [ ] **M2.8. Примеры и conformance-плагин.**
  - Примеры: hello, перевод, кастомная настройка.
  - Conformance-плагин: проверяет доступность всех точек API v1.
  - Проверка: примеры работают; conformance проходит без ошибок.

## M3 — Фичи v1

**Цель:** целиком реализовать заявленный набор фич.

- [ ] **M3.1. Ghost-режим (C++):** дроп/подмена read-history, updateStatus, setTyping,
  просмотра stories; per-account/per-chat; UI и API.
- [ ] **M3.2. Anti-delete (C++):** локальный кэш входящих, отображение и пометка удалённых.
- [ ] **M3.3. Перевод (плагин):** inline-перевод на хуке до отображения.
- [ ] **M3.4. Фичи сообщений (плагины):** anti-edit/история правок, regex-подсветка, spoiler.
- [ ] **M3.5. Кастомизация UI (плагин + тема):** иконки, шрифты, плотность, скругления,
  акцент, скрытие элементов, порядок вкладок.
- [ ] **M3.6. RU-локаль:** RU по умолчанию, переводы строк `extra` в `lang.strings`.
- [ ] **M3.7. Скорость загрузок (C++):** число соединений/параллельных загрузок/префетч,
  консервативные умолчания.
- [ ] **Проверка:** каждая фича включается/выключается; функциональный прогон на живом аккаунте.

## M4 — Дистрибуция

**Цель:** установочные пакеты и обновления.

- [ ] **M4.1. CI (GitHub Actions):** сборка Linux static через docker-окружение tdesktop.
- [ ] **M4.2. AppImage.**
- [ ] **M4.3. `.deb` и `.rpm`.**
- [ ] **M4.4. Flatpak** (манифест, собственный app id).
- [ ] **M4.5. AUR** (PKGBUILD).
- [ ] **M4.6. In-app updater** на собственные релизы.
- [ ] **Проверка:** установка пакетов на чистых системах/в контейнерах; обновление проходит.

## Журнал швов (заполняется по ходу)

Формат записи в `SEAMS.md`: `файл → якорь в коде → вызов → назначение → как проверить`.

Первый шов (M0.5): диспетчер входящих апдейтов → `Extra::Hooks::OnUpdate(...)` → заглушка.
