# Спецификация: ПК-клиент в стиле ExteraGram

- **Рабочее имя:** XunGram (плейсхолдер, меняется)
- **Дата:** 2026-10-12
- **Статус:** утверждён к планированию

## 1. Обзор и цель

ExteraGram — это сторонний Telegram-клиент для Android: форк официального клиента с
набором дополнительных функций и встроенным движком плагинов на Python. Цель проекта —
создать аналогичный клиент для персонального компьютера (в первую очередь Linux):
форк официального `tdesktop` (Qt6/C++) с собственной **открытой** системой плагинов на
Python, которая позволяет пользователям писать собственные расширения.

Главная ценность — не «ещё один клиент», а **платформа**: базовая функциональность
Telegram наследуется от tdesktop, а отличия даёт плагинный API и набор встроенных фич,
реализованных на этом же API.

## 2. Цели

- Рабочий Telegram-клиент под Linux, форк `tdesktop`, с собственным API id и брендингом.
- Публичный Python-API, достаточный, чтобы сообщество писало плагины без правок C++.
- Встроенные фичи v1: ghost-режим, фичи сообщений/чатов, глубокая кастомизация UI,
  русская локализация, ускорение загрузок.
- Дистрибуция: AppImage, `.deb`, `.rpm`, Flatpak, AUR.
- Минимизировать конфликты с апстримом: наши изменения изолированы в отдельном слое,
  апстрим-файлы трогаются только в документированных «швах».

## 3. Не-цели (v1)

- Стор плагинов с ревью, рейтингами и авто-обновлением — отложено (установка из файла/URL).
- Кроссплатформенность (Windows/macOS) — задел есть, но v1 только Linux.
- Песочница плагинов — сознательно исключена (см. §4 и §11).
- Собственная реализация протокола MTProto / замена TDLib — не делаем, используем tdesktop.

## 4. Ключевые решения (зафиксированные)

| Решение | Выбор | Обоснование |
|---|---|---|
| Фундамент | Форк `tdesktop` 7.3.x + CPython | Быстрый путь к полной функциональности |
| Язык плагинов | Python 3.12 | Привычно сообществу ExteraGram |
| Модель плагинов | In-process, максимальная власть | Гибкость и простота; ExteraGram-подобный опыт |
| Песочница | Нет | Осознанный риск; компенсируется предупреждениями и подписью |
| Слой поверх апстрима | Изолированный + регулярный merge | Поддерживаемость |
| Связка фич и API | Гибрид (подход C) | Hot-path фичи на C++, кастомизация на Python |

## 5. Архитектура

### 5.1 Структура репозитория

```
repo/
├── tdesktop/                     # форк upstream, remote `upstream` для merge
│   └── Telegram/SourceFiles/
│       ├── ...                   # апстрим, не трогаем кроме швов
│       └── extra/                # НАШ C++ слой (новая директория)
│           ├── seam/             # точки внедрения в апстрим
│           ├── host/             # встраивание CPython + pybind11
│           ├── features/         # нативные hot-path фичи (ghost, anti-delete, скорость)
│           └── ui/               # вкладка «Плагины», менеджер, safe mode
├── plugins/                      # ВСТРОЕННЫЕ Python-плагины = фичи v1
│   ├── translate/
│   ├── customize/
│   └── ...
├── sdk/                          # Python SDK: .pyi-стабы, доки, примеры
└── packaging/                    # deb / rpm / flatpak / AUR / AppImage
```

### 5.2 Принцип изоляции

- Вся бизнес-логика живёт в `extra/`, `plugins/`, `sdk/`, `packaging/`.
- В апстрим-файлы вносятся только «швы» — единичные вызовы вида `Extra::Hook::...`.
- Каждый шов фиксируется в `SEAMS.md` (файл, контекст, назначение) для быстрого
  переприменения при merge с `upstream`.
- Единственная крупная правка сборки — `add_subdirectory(extra)` и группы источников
  в `Telegram/CMakeLists.txt`.

### 5.3 Потоки данных

```
Telegram servers
      │  MTProto (bitstream)
      ▼
tdesktop mtproto ──► [SEAM] ──► Extra::Hooks::OnRequest / OnUpdate
      │                                  │
      │                                  ├─► C++ features (ghost: drop/rewrite)
      │                                  └─► Plugin engine ──► Python plugins
      ▼
apiwrap / storage ──► [SEAM] ──► OnOutgoingMessage / OnIncomingMessage
      ▼
UI render ──► [SEAM] ──► OnRenderMessage / UI registries
```

Приоритет обработки: сначала C++ features (быстрые, критичные), затем плагины. Шов
предоставляет возможность «изменить/отменить» промаркированную операцию.

### 5.4 Компоненты C++ слоя

- `Extra::Hooks` — статический реестр точек расширения и диспетчер вызовов.
- `Extra::Plugins::Engine` — загрузка/выгрузка/перезагрузка плагинов, реестр, изоляция
  ошибок, safe mode.
- `Extra::Plugins::Bindings` — pybind11-обёртки публичного API.
- `Extra::Bindings::Session` — фасад над сессией/аккаунтом для плагинов.
- `Extra::Features::Ghost`, `::AntiDelete`, `::DownloadTuning` — нативные фичи.
- `Extra::Ui` — страница настроек «Плагины», менеджер, диалоги установки.

## 6. Движок плагинов

### 6.1 Формат плагина

Плагин — директория:

```
my_plugin/
├── manifest.json     # id, name, version, api_version, author, permissions, entry
└── main.py           # точка входа, наследует BasePlugin
```

`manifest.json`:

```json
{
  "id": "com.example.hello",
  "name": "Hello Plugin",
  "version": "1.0.0",
  "api_version": 1,
  "author": "someone",
  "entry": "main.py",
  "permissions": ["messages.read", "messages.send", "ui.settings"]
}
```

### 6.2 Базовый класс и жизненный цикл

```python
from xungram import BasePlugin, hooks

class HelloPlugin(BasePlugin):
    def on_load(self):
        pass

    def on_enable(self):
        self.mark_read = self.get_setting("mark_read", True)

    @hooks.on_incoming_message
    def handle(self, msg):
        if not self.mark_read and msg.chat.id == 123:
            hooks.cancel_read()
        if msg.text and "hi" in msg.text.lower():
            hooks.replace_text(msg.text + " 👋")

    def on_disable(self):
        pass

    def on_unload(self):
        pass
```

Хуки жизненного цикла: `on_load`, `on_enable`, `on_disable`, `on_unload`,
`on_settings_changed`.

### 6.3 Точки расширения (API v1)

- **Сеть:** `on_request` (исходящие запросы: изменить/заблокировать), `on_update`
  (входящие апдейты: наблюдать/модифицировать до применения).
- **Сообщения:** `on_outgoing_message` (до отправки: изменить/отменить), `on_message_sent`,
  `on_incoming_message` (до отображения: изменить текст/разметку, пометить).
- **UI:** `register_settings_page`, `register_settings_row`, `show_dialog`, `show_toast`,
  `register_menu_item`, `register_shortcut`.
- **Сессия:** `send_message`, `edit_message`, `send_media`, `list_chats`, `get_chat`,
  `current_account`.
- **Настройки:** `get_setting`/`set_setting` (изолированный KV-store), авто-UI, экспорт/импорт.
- **Утилиты:** `run_on_ui`, очередь фоновых задач, логирование.

### 6.4 Модель выполнения и GIL

- Колбэки плагинов по умолчанию вызываются в UI-потоке.
- Для тяжёлой работы — `run_on_ui()` / фоновые очереди.
- При вызове Python из Qt-потока GIL захватывается управляемо; долгие операции не
  блокируют UI-поток.
- Любое исключение плагина перехватывается, логируется, плагин помечается сломанным и
  отключается; клиент продолжает работу.

### 6.5 Версионирование

- `PLUGIN_API_VERSION` (int) и capability-negotiation.
- Плагин декларирует `api_version`; несовместимость → отказ загрузки с понятным сообщением.
- Ломающие изменения — только с мажорным повышением API.

## 7. Фичи v1

Всё реализуется на публичном API; нативные фичи дополнительно экспонируются в Python.

### 7.1 Ghost-режим (C++)

- Шов на пути отправки MTP: при включённом режиме дропаются/подменяются
  `messages.readHistory`, `channels.readHistory`, `account.updateStatus`,
  `messages.setTyping`, отметки просмотра stories.
- Гранулярность: per-account и per-chat (белый список исключений).
- UI-переключатели в настройках, доступ из плагинов.
- Риск: влияние на корректность счётчиков непрочитанного — покрыть тестами.

### 7.2 Фичи сообщений/чатов

- **Anti-delete (C++):** локальный кэш входящих; удалённые остаются видимы и помечаются.
- **Перевод (плагин):** `messages.translateText` или внешний API, inline-подмена.
- **Anti-edit / история правок, regex-подсветка, spoiler (плагины):** хук «до отображения».

### 7.3 Глубокая кастомизация UI (плагин + расширение темы)

- Пакеты иконок и шрифтов, плотность, скругления, акцент, скрытие элементов, порядок вкладок.
- Часть уже покрывает система тем и стилей tdesktop — расширяем её; остальное через API рендера.

### 7.4 RU-локализация

- Русский в tdesktop уже есть — делаем дефолтом, добавляем переводы наших строк в `lang.strings`.

### 7.5 Скорость загрузок (C++)

- Настройки числа соединений на файл, параллельных загрузок, префетча.
- Соблюдаем лимиты Telegram; значения по умолчанию консервативны.

## 8. Сборка и дистрибуция

- **CMake:** модуль `extra`, статический CPython (vendor) + `pybind11`, встроенные плагины в ресурсах.
- **CI (GitHub Actions):** сборка Linux static через docker-окружение tdesktop; артефакты
  AppImage, `.deb`, `.rpm`, Flatpak, AUR (PKGBUILD).
- **Обновления:** in-app updater на наши релизы; собственный `app id`, desktop-файл, иконки.
- **Установка плагинов (v1):** из файла/директории и по URL; без каталога.

## 9. Тестирование

- C++ швы — через существующий харнесс `Telegram/SourceFiles/test/`.
- Python SDK — unit-тесты; примеры-плагины как интеграционные тесты.
- «Conformance»-плагин — проверяет доступность и поведение публичного API.
- Проверка safe mode и изоляции ошибок (искусственно падающий плагин).

## 10. Безопасность и юридические аспекты

- **Плагины не изолированы** (in-process, полный доступ) — это осознанный выбор. Компенсации:
  предупреждение в UI при установке, отображение запрошенных `permissions`, подпись пакетов,
  safe mode при падении на старте.
- **Юридически:** собственный `api_id`/`api_hash` (my.telegram.org), собственное имя,
  логотип и app id; запрещено выдавать клиент за официальный «Telegram Desktop».
- Код проекта — GPLv3 (наследуется от tdesktop), форк обязан оставаться открытым.

## 11. Риски

1. **Поддержка апстрима.** Частые обновления tdesktop; митигация — изоляция и `SEAMS.md`.
2. **Встраивание CPython в статическую сборку.** Vendor stdlib, размер, совместимость
   glibc/дистрибутивов; митигация — `python-build-standalone`/статический CPython + тесты на пакетах.
3. **Отсутствие песочницы.** Вредоносный плагин может украсть сессию; митигация — подпись,
   предупреждения, документация; в будущем — опциональная песочница.
4. **Юридические.** Свой API id и брендинг обязательны; риск блокировок API при нарушениях ToS.
5. **Производительность хуков.** Перехват горячих путей; митигация — C++ для hot-path,
   быстрый фильтр-диспетчер (плагин подключается только к нужным событиям).

## 12. Вехи (высокоуровнево)

1. **M0 — фундамент:** форк, сборка tdesktop из исходников, собственный API id, `SEAMS.md`.
2. **M1 — хост плагинов:** встроенный CPython, `BasePlugin`, загрузка, менеджер, safe mode.
3. **M2 — API v1 + примеры:** хуки сообщений/сети/UI, SDK со стабами, примеры-плагины.
4. **M3 — фичи v1:** ghost, anti-delete, перевод, кастомизация, RU, скорость загрузок.
5. **M4 — дистрибуция:** AppImage, `.deb`, `.rpm`, Flatpak, AUR, updater.
